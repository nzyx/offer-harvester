## 核心特性

- **向导式三步流程**：`1 简历 → 2 岗位 → 3 产出`。走过的步骤自动收成一行摘要，随时可点回去改；只想快速生成也能一键跳过简历，不强制走完。
- **一键抓取 JD**：在招聘网站的职位详情页点「从当前页面抓取」，自动识别并提取岗位描述正文回填输入框，省掉手动复制。若覆盖了已写内容，可一键撤销。
- **两步串联，质量更高**：先「岗位分析」拆解 JD，再基于分析结果生成「面试准备」——不是凭空编题，而是真正对齐岗位要求。
- **结构化简历字段**：上传简历后可解析成**12 组标准字段**，与网申表单**逐栏对齐**——个人信息 / 求职意向 / 教育经历 / 实习经历 / 项目经历 / 在校职务 / 在校实践 / 附加信息 / 技能 / 获奖情况 / 语言能力 / 证书。全部可逐项核对修改，既是网申自动填表的数据源，也是生成内容的统一输入。字段按**网申表单实际要求的项目**设计，覆盖民族与最高学位、主修课程与专业排名、实习的单位 / 部门 / 职位 / 行业 / 内容 / 成果、项目的名称 / 职务 / 描述 / 成果、技能名称与掌握程度、获奖项与级别、语言类型、证书名称与获得时间等。
- **AI 抽不到的可以自己补，补过的不怕被覆盖**：解析后字段表会列出全部字段（包括简历里没有的），顶部常驻「已填 N 项 · 还缺 M 项（其中必填 K 项）」，可一键跳到下一处空缺或切到「只看空缺」。手工填过的字段会被记住，换一份简历重新解析时只更新 AI 新抽到的部分，**手工补充的内容不会被冲掉**；你删掉的经历条目也不会被重新解析拉回来。
- **个人信息与教育经历不重复填**：个人信息里的最高学历 / 最高学位 / 专业名称 / 毕业学校留空时，自动取教育经历里学历最高、时间最近那一条，只填一处两栏都能用。
- **认得出真实简历的排版**：校招简历普遍写成「`2026.06-2026.8 某公司 产品实习生`」——时间、公司、职位挤在一行，下面跟一串没有字段名的小标题要点。扩展能正确切开这种排版，也能处理日期在行尾（`某公司 产品实习生 2025.07-2025.10`）与常规的「公司：XX」写法。实习的职位、起止时间、工作内容，以及整段项目经历都会抽出来，不再只抓到公司名。
- **网申自动预填**（v1.3 新增）：打开任意公司的网申表单点「网申预填」，自动识别页面上每个控件要填什么，把简历内容填进去并**用红框标出填写位置**。通用语义引擎，**不需要为每家招聘网站做适配**；只填不提交，核对后由你自行提交。敏感字段（身份证 / 银行卡 / 住址 / 紧急联系人）默认不写入。
- **三种产出模式**：面试准备 / 打招呼语 / 简历优化，各适配不同的求职场景。
- **简历文件上传**：支持 `TXT / MD / PDF / DOCX` 本地解析，文件**不上传**，只在本地参与生成。
- **网页复制保护**：一键解除网页复制限制，方便摘录参考资料（侧边栏关闭即失效）。
- **内容记忆**：关闭侧边栏后输入与结果自动保留，浏览器关闭后自动清空（会话级）。
- **一键导出**：任意一份结果都能导出为**自包含的可视化 HTML 网页**，可直接分享或打印成 PDF。
- **错误提示具体到原因**：API Key 无效 / 额度不足 / 模型名写错 / 网络不通 / 请求超时，各自给出可直接操作的提示，而不是笼统的「生成失败」。

## 四种产出模式

### ① 面试准备（岗位分析 + 面试准备）

分两段，且第二段基于第一段的分析结果：

- **岗位分析**：给岗位一句话定位（竞争力评估）→「JD 重点精读」→「关键技能解读」（结构化拆解每项能力 + 行业真实要求）→「隐藏要求挖掘」→「业务背景补充」（含行业术语解释）。
- **面试准备**：「高频面试问题」——预测 6–8 道题目并附**完整参考答案**（STAR + 数字）→「面试现场要点」——被问住时的缓冲话术、反问环节高质量三问、闭环思维表达等实战技巧。

> 关键句会用红色高亮标出，一眼抓住重点。

### ② 打招呼语（Cold Outreach）

- **专业版**：偏完整、体现经历与匹配度的联系 HR 话术。
- **简洁版**：更短、更轻量，适合评论区 / 私信场景。
- **注意事项**：指出你简历与 JD 之间的匹配缺口，并给出「立刻能做的一件事」来补上短板。

### ③ 简历优化（Resume Optimization）

- **匹配度评分**：大号百分比直观展示岗位契合度，附评分依据与明显缺口。
- **经历改写卡**：按「动作 / 方法 / 技术 / 解决问题 / 成果」键值网格重组你的项目经历，像简历条目一样清晰。
- **关键词植入**：建议添加的关键词 + 植入位置，单层编号清单。
- **成品话术**：版本一 / 版本二 两份可直接复制粘贴的完整成稿，与「分析建议」区分开。

### ④ 网申预填（Form Autofill）

在网申页面上点「网申预填」，它会：

1. **扫描页面**：找出所有可见、可编辑的控件（`input` / `select` / `textarea` / `contenteditable`）。
2. **识别语义**：本地规则打分判断每个控件要填什么——标签、`name`、`placeholder`、`autocomplete`、周边文字、所在区块几个维度加权。认不出或含义不明确的字段**选择留空而不是猜**。若已连接 AI，本地认不出的字段会再让 AI 从固定语义枚举里选一次，提高识别率。
3. **给你过目**：分成「将填写」与「需你手动处理」两张清单。前一张显示每个字段将被填的内容与识别到的语义，后一张逐条说明为什么没填。
4. **写入并标记**：点「确认填写」后写入页面，每个填写位置加红框标记。**不点击任何提交按钮。**
5. **收尾**：「清除页面标记」只去掉红框，已填内容保留。

两个开关：**覆盖页面上已有内容**（默认关闭，避免冲掉你已经填好的项）、**包含敏感字段**（默认关闭，身份证 / 银行卡 / 住址 / 紧急联系人不写入）。

## 导出可视化 HTML

每份生成结果右上角都有「**导出 HTML**」按钮，点一下下载一个**自包含网页文件**（无需联网、无外部依赖）：

- 杂志专访页风格：红色 eyebrow + 衬线大标题 + 超大章节编号 + 关键句红色高亮；
- 简历优化模式有专属版式（评分卡 / 经历卡 / 成品话术卡），不与面试准备混用同一套编号；
- 打印友好：导出的 HTML 在打印时自动转成白底、红下划线高亮，适合直接存成 PDF 发给别人；
- 安全：导出文件内**无脚本、无外链**，可放心分享。

## 安装与使用

1. 在 Chrome 打开 `chrome://extensions`，或在 Edge 打开 `edge://extensions`；
2. 开启右上角「**开发人员模式**」；
3. 点击「**加载已解压的扩展程序**」，选择本项目文件夹；
4. 点击工具栏中的「面邀收割机」图标打开侧边栏；
5. 在侧边栏右上角「**设置**」里填写 AI 服务商的**接口地址、API Key、模型名称**，保存即可。

> 未配置 API 时会展示本地演示内容，方便先确认整体流程。

## 支持的 AI 服务商

OpenAI / DeepSeek / Moonshot (Kimi) / 智谱 GLM / 通义千问 / 豆包 / Anthropic (Claude)，以及**任何其他兼容 OpenAI Chat Completions 协议的接口**。

接口地址需填完整的 `.../v1/chat/completions` 路径；本地部署的模型（如 `http://127.0.0.1:8080`）同样支持。

## 数据与隐私

- 无后端服务器，纯前端运行；
- **API Key** 存本地浏览器存储（磁盘持久）；岗位描述、简历内容、生成结果存**会话级存储**，浏览器关闭后自动清空；
- 网络请求**仅**发给你自行配置的 AI 接口，不发给任何第三方；
- 导出的 HTML 文件完全在本地生成，不含任何脚本或外链。

## 常见问题

**Q：没有 API Key 能用吗？**
能。未配置时会展示本地演示内容，方便先确认流程；但要生成真实内容需填入你自己的 AI 接口。

**Q：支持本地模型吗？**
支持。只要接口兼容 OpenAI Chat Completions 协议（如本地 `127.0.0.1:8080`），在设置里填对应地址即可。

**Q：报错「AI输出被输出上限截断且没有可显示内容」怎么办？**
这类报错的根源是模型把输出配额全用在了「思考过程」上，正文一个字都没出来，常见于推理型模型（Qwen3 系列、GLM-Z1、DeepSeek-Reasoner、豆包思考版等）。现在有三层自动处理：

1. **自动关闭思考模式** —— 识别出平台后发送对应的关闭参数（Qwen 系列用 `enable_thinking`，DeepSeek / GLM / 豆包 / 混元用 `thinking`）。
2. **自动放大重试** —— 若仍被截断，把输出上限放大到 `max(2×, 8000)` 重试一次。
3. **自动降级** —— 若依然失败，改用本地规则解析并给出结果，失败原因如实写在结果横幅里。**你不会被卡住。**

想彻底避免，到「设置」把模型换成非思考型，例如 `deepseek-chat`、`gpt-4.1-mini`、`qwen-plus`。结构化抽取是**信息抽取**任务，不需要推理能力，非思考模型的结果一样好，而且更快更便宜。

**Q：为什么「连接诊断」说正常，生成却失败？**
旧版本有这个漏洞：诊断只看了 HTTP 状态码，而思考型模型可能返回 200 但正文为空，于是被误判为「连接正常」。现在诊断会检查响应里**是否真的有正文**，这类模型在诊断阶段就会被点出来，不会等到你真正生成时才发现。

**Q：点「从当前页面抓取」提示没找到岗位描述？**
可能原因有三：① 详情被折叠，先点开「职位详情」再抓；② 该站点把 JD 渲染在 iframe 里，扩展只读主页面，此时请手动复制粘贴；③ 内容以图片渲染，插件不做 OCR。若提示「无法与当前页面通信」，说明网页是在安装/更新扩展**之前**打开的，刷新网页再试即可。

**Q：抓取功能会读取我所有网页的内容吗？**
不会主动读取。扩展只在页面里注册了一个消息监听器，**只有你点「从当前页面抓取」时才执行一次正文提取**，结果直接回填输入框，不外发任何数据。

**Q：网申预填支持哪些招聘网站？**
不需要针对性支持任何一家——它走**通用语义引擎**：读每个控件的标签、`name`、`placeholder` 与所在区块，判断这个字段要填什么，再从你的结构化简历里取对应值。所以理论上任何用标准表单元素（`input` / `select` / `textarea`）的网申页都能用。不做逐站适配器是有意为之：招聘网站改版频繁，一家一个适配器维护不过来。

**Q：网申预填会帮我提交吗？**
不会，这是硬边界。代码里不存在任何点击提交按钮或触发 `form.submit()` 的路径，填充后每个字段会用红框标出，你核对完自己点提交。填完也可以点「清除页面标记」只去掉红框，已填内容不动。

**Q：为什么有些字段没被填上？**
面板上的「需你手动处理」清单会逐条说明原因。常见几类：① **敏感字段**（身份证/银行卡/住址/紧急联系人）默认关闭，需要时打开开关；② **简历里没有**这个信息，可在第 1 步补充；③ **自定义下拉框**（页面用 `div` 或脚本模拟的 select）与**文件上传**，浏览器安全模型下无法用脚本写入，只能手选；④ **未能识别**或**含义不明确**——这时它选择留空而不是猜，填错比不填更糟。若「本地认不出」的字段较多，到「设置」连接 AI 可显著提高识别率。

**Q：某个字段在清单里看不到，或者明明页面上有却没被识别？**
点预填面板底部的「**有字段没填上？导出诊断详情**」，它会把**扫描到的全部控件**（含未识别与已跳过的）、每个控件**实际读到的标签 / 占位符 / `name` / 章节**、识别结果与跳过原因，导出成一份可复制的报告。

这份报告能区分三种情况：控件**根本没被扫到**（在页面内嵌的框架里，或选择器没命中）／**扫到了但标签没读出来**／**标签读出来了但没规则匹配**。只看那两张清单分不出这几种，因为**没扫到**的控件不会出现在任何清单里，而**标签没读出来**和**没规则匹配**在清单里都只显示「未能识别」——改法却完全不同。报告里那段「未填写控件的原始特征」就是为此存在的。

**Q：为什么有些字段的「标签」显示为「标签为空」？**
那说明扩展没能从页面结构里读出这个字段叫什么，而不是你的简历缺内容。主流招聘系统（北森、Moka、antd 系）会把字段名和控件放在同一个容器里，字段名既不是控件的相邻元素、也不是包着它的 `<label>`，需要从容器文字里反推。扩展已经做了这层反推；若仍读不出来，把诊断报告发出来，报告里能看到每个控件实际读到了什么。

**Q：常见的「学校填不上」是怎么回事？**
院校字段在中大型招聘系统里普遍是**脚本接管的查找型控件**（输入框 + 弹出候选列表），而不是标准下拉框。扩展识别这类控件的依据是 `role=combobox` 或 `aria-haspopup` / `aria-expanded`（点开弹层的标准标记），再分两种处理：

- **输入框可以键入的** → 会把你的学校名**填进搜索框**触发页面自身的筛选，你只要从筛过的候选里点一下即可，不用在几百所学校里翻找。这类在清单和结果提示里都会标注「已填入关键词，请从下拉候选里点选确认」——**没点选之前它不算真正填好**。
- **输入框只读、只能点击弹窗的** → 真的写不进去，跳过并标注「自定义下拉框」，需要你手动选。

所以看到「待点选」提示时，请到页面上把那个下拉点开确认一下。

**Q：手机号前面那个「中国大陆」选择框为什么没被填？**
因为那不是简历字段，而是国家/地区选择框。它很容易被旁边手机号输入框的提示文字带偏、被误判成手机号字段，一旦填进去就是把手机号写进了区号框——比不填更糟。扩展现在会把它单独识别出来并给出「国家/地区选择框」的说明。

**Q：预填必须先在扩展里点「解析」简历吗？**
不需要。有简历原文就能预填：没解析过时用本地规则即时粗解析一遍。但**解析过的结构化简历结果更准**，想填得全还是建议先点一次「解析」。

**Q：复制保护会被商店拒吗？**
复制保护内容脚本覆盖 `<all_urls>` 且改写 `Event.preventDefault`，能力较强，适合自用；若上架 Chrome Web Store 需收窄作用域。

**Q：导出的 HTML 安全吗？**
安全。文件内无 `<script>`、无外链，纯静态，可放心分享。

## 技术栈

- Chrome / Edge **Manifest V3** 侧边栏扩展（side panel）
- 原生 **HTML / CSS / JavaScript**，零框架、零构建工具
- PDF 解析 `pdf.js`、DOCX 解析 `mammoth.js`
- AI 输出采用纯文本 `## 标题` 分块解析，不依赖 JSON
- JD 正文提取用「候选块打分 + 选优」，不做逐站适配器
- 网申预填用「字段语义打分 + 阈值/分差双门槛」，写入受控组件走原型 setter + 事件派发
- 提示词以 `prompts/*.md` 维护，运行时加载
- 验证用 Node 内置能力手写断言脚本，**零测试依赖**（`node tests/*.test.js`）
